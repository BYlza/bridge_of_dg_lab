# Bridge of DG-LAB — 一页纸方案

> 死亡搁浅一代 × 郊狼（DG-LAB）触觉反馈连接器
> 版本：v0.1 设计稿 ｜ 日期：2026-11-24 ｜ 状态：待评审

## 1. 问题

《死亡搁浅》里"受伤"是核心叙事体验，但玩家只能看到血条下降。郊狼 3.0 已经开放 Socket 控制协议，社区也已在《半条命 2》《我的世界》《杀戮尖塔 2》里做出同类联动——**唯独《死亡搁浅》没有成品**。

## 2. 调研结论

| 方向 | 现状 | 对我们的价值 |
|---|---|---|
| 死亡搁浅 × 郊狼 | **无成品**（Nexus / GitHub / 中文社区均未检索到） | 空白，可做第一份 |
| 郊狼官方 Socket 协议 | 开源、文档完整、3.0 主机可用 | **协议层零成本复用** |
| 半条命 2 受伤 Mod | 游戏内掉血 → 按伤害百分比给强度，玩家死亡给 5 秒满强度 | 最接近的参考实现（规则可直接借鉴） |
| 我的世界 Blank-DG-LAB | 伤害类型分级、低血量持续脉冲、A/B 独立通道、软上限 | 映射模型参考 |
| 郊狼游戏中心 / PyDGLab-WS | HTTP/WS 控制端、Python 协议库 | 可直接当连接器底座 |
| 死亡搁浅 Mod 工具链 | 有 Decima Workshop（改资源）、CE 表（血量/耐力指针）、ASI 代理 DLL（`version.dll`）、MinHook 原生 Mod（Walking-Man） | **两条技术路线都成立** |

**判断：做，而且先做纯外部读取的独立程序，不碰游戏文件。**

## 3. 方案

**MVP（推荐先做）**：单进程 Python 程序
`读游戏内存（pymem / ReadProcessMemory）→ 伤害事件识别 → 强度映射 → 本地 WebSocket → 郊狼 App`

- 只读内存，不注入、不改 exe、不打补丁 ⇒ 崩溃风险最低，反作弊风险最低
- 代价：只能拿到"数值变化"，拿不到"伤害类型/来源"，延迟约 16–33 ms

**v2（可选增强）**：ASI 插件（`version.dll` 代理 + `.asi`，MinHook 挂伤害写入点）
- 能拿到精确伤害事件、伤害类型、攻击者，延迟 < 5 ms
- 代价：随游戏版本失效、需维护特征码、有崩溃面

两者共用同一套"连接器 + 映射引擎"，插件只作为事件源替换。

## 4. 关键映射（草案）

| 游戏信号 | 通道 | 反馈形态 |
|---|---|---|
| 受到伤害（按占最大生命百分比） | A | 短促打击波，幂律校准 `I = Imax · (dmg/maxHP)^0.7` |
| 摔倒 / 高处坠落 | A | 单次强脉冲 + 3 秒余震 |
| 敌人枪击 / BT 拖拽 | A | 锐利短脉冲 / 递增持续 |
| 生命低于 30% | B | 心跳节律，随血量下降加密 |
| BB 压力升高 | B | 低频"闷"脉冲（可关） |
| 时间雨暴露 | A | 极低频麻感，随暴露累积 |
| 死亡 | A | 满强度 3 秒（可配），随后**强制归零** |

安全约束是硬性的：全局上限 ≤ App 上报上限、强度上升限速、3 秒无事件衰减归零、急停热键、连续输出超时冷却。

## 5. 风险

1. **偏移失效**——游戏更新即崩。对策：AOB 特征码 + 按版本配置文件 + 启动自检，读不到就拒绝输出。
2. **误判**——读档/传送/菜单会让血量跳变。对策：暂停检测 + 变化率过滤 + 死区。
3. **电刺激安全**——这是真实物理输出。对策：默认强度极低、硬上限、看门狗、物理断电为最终手段。
4. **合规**——仅单机离线使用，不内置成人内容，遵守直播平台规则。

## 6. 里程碑

| 阶段 | 内容 | 产出 |
|---|---|---|

| M1 | 读到血量：CE 定位 + 指针链 + AOB | 终端打印血量曲线 |
| M2 | 映射引擎 + 托盘 UI + 急停 | 可玩 MVP |
