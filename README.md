# Bridge of DG-LAB

把《死亡搁浅》里 Sam 的伤痛，变成你身上真实的触觉反馈。

一个独立进程：**只读**游戏内存 → 识别伤害 → 驱动[郊狼 3.0](https://www.dungeon-lab.com/) 输出。不改游戏文件、不注入进程、不需要任何 Mod。

> **状态**：v0.1，已在《死亡搁浅 导演剪辑版》1.004 + 郊狼 3.0 上实测跑通。

---

## 效果

摔一跤掉 150 血（15%），B 通道 20 ms 内升到 16，约 0.7 秒衰减回 0 —— 一次干脆的"打击感"，不是持续电着。

| 掉血 | 占比 | A 通道（上限 1） | B 通道（上限 30） | 达峰 | 衰减到 10% |
|---|---|---|---|---|---|
| 10 | 1% | 0 | 0 | —（死区内忽略） | — |
| 30 | 3% | 0 | 12 | 10 ms | 0.7 s |
| 116 | 11.6% | **1** | 15 | 20 ms | 0.7 s |
| 150 | 15% | 1 | 16 | 20 ms | 0.7 s |
| 400 | 40% | 1 | 20 | 25 ms | 0.7 s |
| 1000 | 100% | 1 | 27 | 30 ms | 0.7 s |

两点容易误会的地方，先讲清楚：

- **A 通道上限配成 1，本质是「有/没有」两档。** 只有掉血 ≥ 116 才会输出 1，小擦伤它不响。想要连续手感就把 `max_intensity_a` 调到 5–10。
- **B 通道永远到不了 30。** 上升速度 26/s 追不上 0.3 s 的衰减，1 秒内峰值约 27。这是刻意的：宁可留余量，也不让设备顶在上限。

除了单次脉冲，还有：

- **双通道独立**：A / B 可单开可同开，各自上限、各自钳制。
- **读档、传送不误触**：单次血量跳变超过 35% 直接判定为读档/重生，重置基线，不打一发。
- **地址失效自动重定位**：退出游戏后血量地址会变，程序按「上次血量 → 满血」自己重扫（约 35 秒），也可以在页面上填当前血量手动定位。
- **设置页面**：实时血量条、双通道输出、回环延迟、最近受伤记录、曲线模拟器（用运行中的同一套映射代码算）。
- **默认预览**：不加 `-Arm` 绝对不输出，只打印。

## 快速开始

前置：Windows + Python 3.12 + `pip install pydglab-ws qrcode`。

### 一条命令启动

```powershell
.\start.ps1 -Arm -Channel B
```

**想先确认安全？去掉 `-Arm` 就是预览模式** —— 一样会连设备、读血量、在设置页面显示状态，但不会输出：

```powershell
.\start.ps1
```

也可以直接双击 `start.cmd`：默认预览模式，出错时窗口会停住方便你看原因。

脚本会自己切到项目目录、找到可用的 Python、检查依赖，缺什么直接告诉你装什么。

| 参数 | 作用 | 默认 |
|---|---|---|
| `-Arm` | 真的驱动输出；不加就是预览 | 关 |
| `-Channel A\|B\|dual` | 驱动哪条通道 | 读 `config/app.json` |
| `-HostIp <地址>` | 二维码里写的地址（换网络时用） | 读 `config/app.json`，没有再自动探测 |
| `-Python <路径>` | 指定解释器 | 自动找 `python` |
| `-DebugLog` | 打印每次输出/回读细节 | 关 |
| `-DryRun` | 只打印将要执行的命令，不启动 | 关 |

### 启动之后

1. 终端出现二维码 → 手机 DG-Lab App → **SOCKET 控制** → 扫码绑定；
2. 浏览器打开 <http://127.0.0.1:8765> 看血量、输出强度、调曲线，测试和急停都在这个页面；
3. 要停：终端按 `Ctrl+C`（自动归零），或者直接关掉郊狼主机电源。

终端每 2 秒打一行状态：

```
  血量=735.0000  A=1.0 B=7.4  峰值= 32%  ARMED  上限 A=1/B=30 看门狗=3s 累计输出=12s/1800s
```

### 换网络 / 手机扫码连不上

二维码里的地址是**启动那一刻**取的，换 Wi-Fi、换热点、Tailscale 重连之后要重启并指定地址：

```powershell
.\start.ps1 -Arm -Channel B -HostIp 192.168.1.42
```

也可以用环境变量（优先级：`-HostIp` > `BRIDGE_PUBLIC_HOST` > `config/app.json` > 自动探测）：

```powershell
$env:BRIDGE_PUBLIC_HOST = "192.168.1.42"   # 换成你自己的地址
.\start.ps1 -Arm -Channel B
```

> App 只接受 `ws://`，`wss://` 隧道（ngrok / Cloudflare Tunnel）扫码会直接失败。

### 不用脚本，手动跑

```powershell
python -m bridge                  # 预览
python -m bridge --arm --channel B
python tests/test_protocol.py     # 协议自检，不需要手机与设备
python tools/bench_ws.py          # 只测「电脑 ↔ 手机 ↔ 郊狼」链路
```

## 设置页面

启动后浏览器打开 **<http://127.0.0.1:8765>**（端口在 `config/app.json` 的 `web_port`）。页面每 300 ms 拉一次状态，不需要刷新。

顶部三个状态标签：`已连接 / 等待扫码`、`ARMED / 预览`、`延迟 xx ms`（低于 150 ms 变绿，用于判断手机回环是否正常）。

### 血量

- 当前血量 / 上限、百分比，以及一条渐变血条（低于 25% 变红）；
- 紫色曲线是最近约 36 秒的**输出强度**（不是血量），用来回看一眼伤害脉冲长什么样；
- 下方是最近 8 次受伤记录：时间、掉血多少、峰值百分比。

### 血量地址失效（只在失效时出现）

退出游戏或读档后血量地址会变，这张卡片才会弹出来：

- 在输入框填**游戏里当前显示的血量数字**（1–1000）→ 点「重新定位」；
- 后台跑 `tools/relocate.py` 扫内存，约 35 秒，别关窗口；
- 成功后主程序自动重新附加；没找到会提示核对数字。多数情况程序自己按「上次血量 → 满血」就恢复了，不用你动手。

### 输出

- A / B 两条实时输出条，右边是「当前 / 上限」；B 通道还会额外标注 App 上报的上限（`App 150` 这种），实际输出取两者较小值；
- **测试 A（2 秒）／ 测试 B（2 秒）**：脱离游戏单独试强度，测试期间游戏联动自动暂停，结束立刻归零；
- **急停归零**：双通道强度清零 + 清空波形队列，同时重置映射状态。

### 通道设置 / 曲线

| 控件 | 作用 |
|---|---|
| 启用通道 | 仅 A / 仅 B / A+B |
| A 通道上限、B 通道上限 | 硬上限，和 App 上报的上限取最小值 |
| 小伤害保底 `floor_ratio` | 只要受伤，至少给到上限的这个比例 |
| 曲线 `gamma` | 越小则小伤害越有感知 |
| 上升速率 `rise_rate` | 每秒涨满量程的倍数 |
| 衰减时间 `τ` | 越大，余韵越长 |
| 死区 `deadzone` | 伤害占最大生命低于此值直接忽略 |

**拖动即时生效**（直接作用到正在运行的映射上），但**不会写文件**；点「保存」才写回 `config/app.json`，点「放弃修改」重新读回。拖动过程中页面不会被状态轮询覆盖。

### 输出模拟

拖动「模拟掉血」或直接点 `轻伤 30` / `摔一跤 150` / `重摔 400` / `致命 1000`，会用**和实际运行完全相同的映射代码**算一遍，画出 A/B 两条曲线，并给出峰值、达峰时间、衰减到 10% 的时间。

调参数前先在这里看一眼，比真身上试安全得多。

> ⚠️ 这个页面**没有任何认证**，只监听 `127.0.0.1`。不要把 `web_host` 改成 `0.0.0.0`，也不要把 8765 做端口转发 —— 那等于把电击设备的控制权交给同网段的任何人。

## 配置

首次使用先复制示例：`copy config\app.example.json config\app.json`。改文件要重启才生效；在设置页面上改则即时生效。

| 字段 | 含义 | 示例值 |
|---|---|---|
| `channel_mode` | `A` / `B` / `dual` | `DUAL` |
| `max_intensity_a` | A 通道硬上限（0–200，受 App 上限二次限制） | `1` |
| `max_intensity_b` | B 通道硬上限 | `30` |
| `floor_ratio` | 只要有伤害，至少给到上限的这个比例 | `0.25` |
| `gamma` | 幂律指数，越小则小伤害越有感知 | `0.45` |
| `rise_rate` | 上升速度（每秒涨满量程的倍数） | `26` |
| `decay_tau` | 衰减时间常数（秒） | `0.3` |
| `deadzone` | 伤害占最大生命低于此值就忽略 | `0.017` |
| `jump_ratio` | 单帧跳变超过此比例视为读档/重生 | `0.35` |
| `watchdog_sec` | 多久没有有效事件就归零 | `3` |
| `session_limit_sec` | 累计输出上限，到点强制冷却 | `1800` |
| `cooldown_sec` | 冷却时长 | `60` |
| `public_host` | 二维码里的地址，`null` 表示自动探测 | `null` |
| `web_host` / `web_port` | 设置页面监听地址 | `127.0.0.1` / `8765` |

页面上的滑块改动**立刻生效但不写文件**，点「保存」才写回 `config/app.json`。

## 故障排查

| 现象 | 原因 | 办法 |
|---|---|---|
| 扫码后 App 提示连接失败 | 手机和电脑不在同一网段，或二维码里是旧地址 | 重启程序并用 `-HostIp` 指定当前网卡地址 |
| 一直停在「等待扫码」 | 防火墙拦了入站 5678 | 跑一次 `tools\allow_firewall.ps1`（需管理员） |
| 打开进程失败、错误码 5 | 游戏以管理员权限运行 | PowerShell 也用管理员权限打开 |
| 页面提示「血量地址失效」 | 退出游戏 / 读档后堆地址变了，属正常 | 等自动重定位（约 35 秒），或填当前血量 |
| 血量读数乱跳 | 加载过程中的脏数据 | 程序容忍 8 秒再判定失效，不用管 |
| A 通道一直没反应 | 上限 1 + 只有掉血 ≥116 才输出 1 | 把 `max_intensity_a` 调到 5–10 |
| 端口 8765 被占用 | 已有实例在跑 | 关掉旧实例，或改 `web_port` |

## 原理

```
ds.exe（游戏进程）
   │   ReadProcessMemory 读血量 int32，10 Hz，只读不写
   ▼
Bridge of DG-LAB（独立进程：伤害映射 + 安全钳制）
   │   ws://<本机IP>:5678，扫码绑定
   ▼
郊狼 App（手机）
   │   BLE
   ▼
郊狼 3.0 主机
```

**读内存**：`OpenProcess` 只申请 `PROCESS_VM_READ | PROCESS_QUERY_INFORMATION`，用 `ReadProcessMemory` 直接读，不写、不注入。血量地址是会话级的堆地址，所以有 `tools/relocate.py` 按「int == 当前血量，且后 8 字节是两份 N/1000 的 float」这个结构特征重扫（8 进程并行，约 35 秒）。

**映射**：

```
目标强度 = floor_ratio + (1 - floor_ratio) · (Δ / maxHP)^gamma
实际上升 = min(level + rise_rate · dt, 目标)
自然衰减 = level · exp(-dt / decay_tau)
```

**安全层**（`bridge/safety.py`，输出前必过）：

1. 硬上限 = `min(配置上限, App 上报的通道上限, 200)`，取三者最小；
2. 上升限速，禁止一帧从 0 跳到满；
3. 看门狗：3 秒没有新的伤害事件 → 归零并清空波形队列；
4. 累计输出 30 分钟 → 强制归零，冷却 60 秒；
5. `Ctrl+C`、异常退出、App 断连、地址失效 → 一律归零。

## 隐私

- **只读**：不修改游戏内存、不改游戏文件、不注入进程。
- **不上传**：没有任何遥测。数据只在本机走两条路 —— 本机 WS（5678）发给手机 App，本地页面（8765）给你自己看。
- **不落盘**：除了 `out/last_hp.txt`（记录上次血量用于自动重定位）和 `out/qr.svg`（二维码），不写任何东西。
- **配置不外泄**：`config/app.json` 里是你的网络地址，已被 `.gitignore` 排除，仓库里只有 `config/app.example.json` 模板。

## 已知限制

- **设置页面没有任何认证**，只监听 `127.0.0.1`。**不要把 `web_host` 改成 `0.0.0.0`，也不要把 8765 做端口转发** —— 那等于把电击设备的控制权交给同网段的任何人。
- **没有全局急停热键**。急停手段是：`Ctrl+C`、设置页面的「急停归零」、或物理断电。
- 血量地址是**会话级**的，重启游戏后需要重定位（程序会自动做）。
- 只支持**郊狼 3.0**（Socket 控制）；2.0 只能走蓝牙方案。
- 仅单人离线模式。线上/多人模式下的行为未验证，也不建议。
- 只在导演剪辑版 1.004 上实测过；其他版本需要重新找血量地址。
